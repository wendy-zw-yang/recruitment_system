## 说明

- 本文档采用 **PlantUML** 描述用例图，每张图为独立 ` ```plantuml ` 代码块，可在 VSCode 中用 PlantUML 插件直接预览。
- **图层结构**：3 层共 7 张图
  - **总览级**（1 张）：跨 3 角色 + AI 服务的全部用例
  - **角色级**（3 张）：候选人 / HR / 管理员各自的详细用例图
  - **专题级**（3 张）：消息中心 / 投递状态机 / AI 集成
- **用例粒度**：40 个用例（覆盖功能性需求分析 v1.1 全部 4.x 章节 + 扩展 AI 功能）
- **关键关系**：
  - `A ..> B : <<include>>` —— A 必须触发 B
  - `A ..> B : <<extend>>` —— B 在 A 的特定条件下触发
  - `Actor --> Usecase` —— actor 与用例的直接关联

```plantuml
    usecase "HR 发送消息" as H_Send
    usecase "HR 接收消息" as H_Recv
    usecase "HR 接收系统通知" as H_Notify
    usecase "上传/下载消息附件" as MsgAtt

    usecase "会话创建" as ConvCreate
    usecase "SSE 长连接推送" as SSE
    usecase "轮询兜底（3-5s）" as Poll
    usecase "自动标记已读" as ReadFlag
}

C --> C_Send
C --> C_Recv
C --> MsgAtt

H --> H_Send
H --> H_Recv
H --> H_Notify

SYS --> H_Notify : <<trigger>>
SYS --> ReadFlag

' 会话关系
C_Send ..> ConvCreate : <<include>>
H_Send ..> ConvCreate : <<include>>

' 消息接收
C_Recv ..> SSE : <<include>>
C_Recv ..> Poll  : <<extend>>
H_Recv ..> SSE : <<include>>
H_Recv ..> Poll  : <<extend>>

' 已读
C_Recv ..> ReadFlag : <<include>>
H_Recv ..> ReadFlag : <<include>>

' 附件
C_Send ..> MsgAtt : <<extend>>
H_Send ..> MsgAtt : <<extend>>

note right of ConvCreate
  **二元组唯一**
  - (HR, 候选人) 唯一会话
  - 跨职位共享同一会话
  - job_id 下放到 message 级
end note

note right of SSE
  **实时推送**
  - 主路径：SseEmitter
  - 兜底：3-5 秒轮询
  - 不引入 WebSocket
end note

note right of H_Notify
  **自动通知触发场景**
  - 候选人撤回投递（UC14）
  - 内容示例："候选人 X 已撤回对职位 Y 的投递"
end note

@enduml
```

## 6. 投递状态机专题用例图

```plantuml
@startuml
left to right direction
title 投递状态机专题用例图

actor "求职者" as C
actor "HR" as H

rectangle "投递状态机子系统" {

    usecase "投递职位" as Apply
    usecase "AI-2 匹配评分" as Score
    usecase "查看我的投递" as ViewMine
    usecase "撤回投递" as Withdraw
    usecase "查看投递列表（HR）" as ViewList
    usecase "推进投递状态" as Status
    usecase "查看候选人完整简历" as ViewResume

    usecase "PENDING_REVIEW 待处理" as S1
    usecase "VIEWED_BY_HR 已查看" as S2
    usecase "RESUME_PASSED 简历通过" as S3
    usecase "INTERVIEWING 面试中" as S4
    usecase "OFFERED 已发 offer" as S5
    usecase "HIRED 已入职" as S6
    usecase "REJECTED 已拒绝" as S7
    usecase "WITHDRAWN 已撤回" as S8
}

C --> Apply
C --> ViewMine
C --> Withdraw

H --> ViewList
H --> Status
H --> ViewResume

' 投递 → 评分
Apply ..> Score : <<include>>\n（投递瞬间一次）

' 状态推进 → 8 状态
Status ..> S1 : <<state>>
Status ..> S2 : <<state>>
Status ..> S3 : <<state>>
Status ..> S4 : <<state>>
Status ..> S5 : <<state>>
Status ..> S6 : <<state>>
Status ..> S7 : <<state>>

' 撤回 → WITHDRAWN
Withdraw ..> S8 : <<include>>\n（任意非终态 → WITHDRAWN）

note right of Apply
  **一次性原则**
  - 投递瞬间触发 AI-2
  - HR 浏览列表不再触发
  - 评分失败 → ai_score=NULL 显示"待评分"
end note

note right of Withdraw
  **WITHDRAWN 终态规则**
  - 仅求职者触发
  - 任意非终态 → WITHDRAWN
  - 不可复活到任何其他状态
  - 自动给 HR 发站内信（→ H_Notify）
end note

note right of Status
  **8 状态合法流转**
  PENDING_REVIEW → VIEWED_BY_HR
  PENDING_REVIEW → REJECTED
  VIEWED_BY_HR   → RESUME_PASSED
  VIEWED_BY_HR   → REJECTED
  RESUME_PASSED  → INTERVIEWING
  RESUME_PASSED  → REJECTED
  INTERVIEWING   → OFFERED
  INTERVIEWING   → REJECTED
  OFFERED        → HIRED
  OFFERED        → REJECTED
  任意非终态 → WITHDRAWN（仅求职者）

  HR 可主动推进或终止任意非终态
  终态：HIRED / REJECTED / WITHDRAWN
end note

note right of ViewList
  **WITHDRAWN 显示**
  - HR 端：默认折叠 + 灰色 + "已撤回"标签
  - 全局搜索默认排除，可筛选显示
  - 状态时间线最后一行展示撤回
end note

@enduml
```

```plantuml
note right of AI1
  **触发位置**：上传瞬间（仅一次）
  **输入**：PDF / Word 附件文本
  **输出**：结构化 JSON
  **降级**：失败 → 提示重传/手动填写
end note

note right of AI2
  **触发位置**：投递瞬间（仅一次）
  **输入**：简历 + JD
  **输出**：0-100 分 + 评分理由
  **降级**：ai_score=NULL，显示"待评分"
  **约束**：HR 浏览列表不再触发
end note

note right of AI3
  **触发位置**：HR 编辑 JD 时（一键润色）
  **输入**：关键词 / 标题
  **输出**：完整 JD 文本
  **降级**：自动切换手动填写
end note

note right of AI4
  **触发位置**：全站悬浮窗口
  **输入**：用户问题
  **输出**：基于使用手册的回答
  **特性**：SSE 流式输出
  **降级**：客服暂不可用提示
end note

note right of AI5
  **触发位置**：HR 投递列表批量操作
  **输入**：候选人简历 + JD
  **输出**：个性化回信草稿
  **状态**：扩展功能
end note

note right of AI6
  **触发位置**：候选人投递时附加
  **输入**：简历 + JD
  **输出**：针对该岗位的求职信

end note

note bottom of AI
```
