## 2. 后端选型

### 2.1 选型理由

- **Spring Boot 3.5.14**：本机 `.m2` 缓存的最新 3.x patch。4.x 的 `spring-boot-starter-web` 被改名为 `spring-boot-starter-webmvc`，MyBatis-Plus 也要换 `spring-boot4-starter`，会带来不必要的样板差异。
- **MyBatis-Plus 3.5.7 + `mybatis-plus-spring-boot3-starter`**：与 Spring Boot 3.x 官方匹配。
- **spring-security-crypto**：仅注册 `BCryptPasswordEncoder` Bean 用于密码哈希，不引入完整 Spring Security（认证方案在需求阶段定）。
- **Maven 3.9.8**：沿用本机已装版本。

## 4. 数据库

### 4.1 MySQL 8.0.46

- 本机已装，**服务名 MySQL80（默认 Stopped / Manual）**，首次启动在「服务」中右键启动即可。
- 字符集：`utf8mb4`
- 排序规则：`utf8mb4_0900_ai_ci`（MySQL 8 默认）
- 引擎：InnoDB

### 4.2 DDL 约定

```sql
CREATE TABLE IF NOT EXISTS <table_name> (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
    <column> <type> NOT NULL DEFAULT ... COMMENT '...',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    is_deleted TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除：0 未删 / 1 已删',
    PRIMARY KEY (id),
    UNIQUE KEY uk_<table>_<col> (<col>),
    KEY idx_<table>_<col> (<col>),
    CONSTRAINT fk_<table>_<ref> FOREIGN KEY (<col>) REFERENCES <other> (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='<table comment>';
```

约定：

- 主键：`BIGINT AUTO_INCREMENT`
- 时间：`DATETIME` + `DEFAULT CURRENT_TIMESTAMP`，更新用 `ON UPDATE CURRENT_TIMESTAMP`
- 软删除：每张业务表加 `is_deleted TINYINT DEFAULT 0`
- 索引命名：`uk_` 唯一键、`idx_` 普通索引、`fk_` 外键
- 所有字段写 `COMMENT`

## 5. 配置文件约定（application.yml）

采用 **单 profile** 结构：主文件 `application.yml` 仅放共享/默认配置；个人本地配置放 `application-local.yml`，通过 `spring.profiles.active=local` 默认激活。`application-local.yml` 必须加入 `.gitignore`。

### 5.1 application.yml（提交进 git）

```yaml
spring:
  application:
    name: recruitment-system
  profiles:
    active: local
  servlet:
    multipart:
      max-file-size: 20MB        # 简历上传上限
      max-request-size: 20MB

mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl

llm:
  api-url: ${LLM_API_URL:https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions}
  api-key: ${LLM_API_KEY:}
  model: ${LLM_MODEL:qwen-plus}
  timeout-seconds: 30
```

### 5.2 application-local.yml（加入 .gitignore）

```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:${DB_PORT:3306}/recruitment_system?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${DB_USER:root}
    password: ${DB_PASSWORD:}
    driver-class-name: com.mysql.cj.jdbc.Driver

logging:
  level:
    com.example.recruitmentsystem: debug
```

所有 host / port / 账号 / API Key 全部走 `${ENV_VAR:默认值}` 占位，后续如迁移到 Linux 服务器只需改环境变量，不动代码。

## 6. 大模型 API 集成

### 6.1 提供方对比

| 提供方 | 模型示例 | 端点 | 兼容性 |
|---|---|---|---|
| 通义千问（默认） | qwen-plus / qwen-turbo | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | OpenAI Chat Completions |
| MiniMax | M3 | `https://api.minimax.io/v1/chat/completions`（国际）/ `https://api.minimaxi.com`（国内） | OpenAI Chat Completions |

两者都使用 `Authorization: Bearer <KEY>` + JSON body，**通过修改 `llm.api-url` / `api-key` / `model` 三个字段即可切换**，不写两套调用代码。

### 6.2 工程化做法

参考已有项目的分层：

```
config/LlmConfig.java                      # @ConfigurationProperties("llm") 读取 YAML
service/<domain>/LlmService.java           # 接口
service/<domain>/impl/LlmServiceImpl.java  # 实现
dto/<domain>/Llm<Domain>Request.java       # 请求 DTO
dto/<domain>/Llm<Domain>Response.java      # 响应 DTO
```

要点：

1. **API Key 不进 git**：`application-local.yml` 写实际值，加入 `.gitignore`。
2. **结构化输出**：调用大模型时设置 `response_format={"type":"json_object"}`，并在系统提示词中给出 JSON Schema。
3. **超时控制**：读取 `llm.timeout-seconds`，避免长任务阻塞业务线程。
4. **占位/降级**：未配置 API Key 时返回明确错误而非崩溃，便于本地不接 Key 也能跑通业务流程。

## 11. Python 工具脚本（软约束 / 可选扩展）

> 本节为软约束，按用户授权（2026-09-26）加入；不影响 Java 为主栈的主路径。

### 11.1 定位
- `tools/ 目录下的 Python 脚本为**软依赖**，用于辅助开发与特定场景加速，不进入运行时主路径
- 当前用例：简历附件解析（PDF / Word → 结构化文本）由 Java 通过 ProcessBuilder 调起
- 默认业务路径仍是 Java（HTTP 调用 LLM、状态推进、CRUD 等），Python 仅在 Java 调用解析脚本时被拉起

### 11.2 集成方式（Java → Python 子进程）
- 调用入口：Java ProcessBuilder 执行 python tools/parse_resume.py <input_path>
- 输入：简历文件绝对路径
- 输出：stdout 输出 JSON（如 {"text": "...", "pages": N, "format": "pdf|docx"}），Java 解析后用于 LLM 调用
- 进程超时：30 秒（与 LLM 超时同档，避免阻塞业务线程）
- 失败回退：脚本未找到 / 非零退出码 → Java 自动回退到 Apache PDFBox / POI 实现（pom.xml 按需加入）

### 11.3 运行时与依赖
- Python 3.11+（本机已装 3.12.2）
- 依赖库：pdfplumber（PDF 文本抽取）、python-docx（Word 段落 / 表格）
- 虚拟环境：`tools/.venv/（**不提交**，加入 .gitignore）
- 依赖清单：`tools/requirements.txt

### 11.4 软约束边界（不引入）
- **不**引入 Python Web 框架（FastAPI / Flask 等），不部署 Python 微服务
- **不**引入 LangChain / LlamaIndex，保持轻量
- 课程项目阶段**不**做单元测试覆盖 Python 脚本（仅黑盒验证：跑通 3-5 个样例文件）
- Python 脚本严禁直接读写业务数据库（MySQL 仍由 Java 独占）
