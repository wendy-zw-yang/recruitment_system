## 追加 · 验证码登录备选方案（v0.8）

### 文件变动

- docs/需求分析.md v0.7 → v0.8

### 改动内容

用户调研 GraduationPathPlatform 的邮箱验证码模式后，决定**增加验证码登录作为密码登录的备选**。

参考项目模式（仅参考模式，不抄业务）：
- MailProperties（pp.mail.enabled 开关）
- MailServiceImpl（if !enabled → console 打印；else → 真发）
- EmailCode 实体（id, email, code, codeType, used, expire_time）
- AuthController 端点对（/auth/login/code 发码 + /auth/code-login 验码）

我们这次的实现（与之前的"邮箱只是数据"决策兼容）：
- **保留**：邮箱是 candidate_profile 必填字段，HR 可见
- **新增**：登录页多一个"用验证码登录"入口
- **开关默认 false**：验证码打印到后端 console，前端响应里告诉用户"控制台查看"
- **不动 SMTP 配置**：演示不需要真发邮件

### 改动清单

1. 7.1 实体清单：账号与认证分组加 mail_code 表（18 张）
2. 3.1.1 / 3.2.1：登录方式改为两种（密码 / 验证码），候选人 + HR 共享
3. 第 9 节决策记录：加 ⑥ 验证码登录

### 后续开发影响（待办）

- 加 spring-boot-starter-mail 依赖到 pom.xml
- 加 pp.mail.enabled / romAddress / romName 到 application.yml
- 实现 MailService + 验证码生成 / 校验 / 过期 / 防爆破逻辑
- 前端登录页加切换 tab

### 答辩价值

开关本身是展示点：
- 能演示"开发态 vs 生产态"
- 讲"配置驱动行为，不改代码"
- 同时展现邮件系统集成能力

## 追加 · HR 公司审核改为异步流程（v0.9）

### 文件变动

- docs/需求分析.md v0.8 → v0.9

### 决策

用户讨论后选 A：**HR 注册即用全部功能，公司审核异步进行**。

理由：演示无需等管理员审核；HR 注册即可用，与求职者体验一致；管理员事后巡查即可。

### 改动内容

1. **3.2.1 注册 / 登录**：
   - 重写 HR 注册流程：邮箱 + 密码 + 公司信息（公司名 / 行业 / 规模 / 简介）
   - 注册后 company.auth_status = PENDING，**HR 立即可用全部功能**（包括发职位）
   - 加注引用 3.3.4

2. **新增 3.3.4 公司审核**：
   - 列表 PENDING 公司
   - 通过 / 拒绝（带理由）+ 可选禁用 HR 账号

3. **决策记录 ⑦ HR 公司审核（异步流程）**

### 公司表新增字段

- uth_status（PENDING / VERIFIED / REJECTED）
- uth_note（拒绝理由）
- erified_at / erified_by

### 显式不做

- 公司邮箱域名校验
- 营业执照上传
- 第三方企业信息 API

### 设计优势

- HR 与求职者登录体验统一（共用验证码 / 密码登录）
- 公司认证仅影响 admin 端，HR 端无感
- 演示时无需先注册 admin 账号审核
