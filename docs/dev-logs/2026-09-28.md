## 设计要点

### 19 张表结构（业务域分组）

| 业务域 | 表数 | 表名 |
|---|---|---|
| 账号与认证 | 2 | user / email_code |
| 简历 | 3 | candidate_profile / resume / resume_attachment |
| 职位与公司 | 2 | company / job |
| 投递 | 3 | application / application_status_history / application_note |
| 收藏 | 1 | favorite_job |
| 消息 | 3 | conversation / message / message_attachment |
| 字典 | 3 | dict_industry / dict_city / dict_skill_suggestion |
| AI 与审计 | 2 | ai_call_log / audit_log |

### 关键设计决策

1. **删除 `user.real_name`，新增 `user.username`**：与需求文档 §3.1.5（个人资料含用户名）+ §4.1.1（注册仅邮箱+密码）一致；真名仅存于 `resume.basic_name`
2. **软删字段统一用 `deleted`**：与 `docs/技术约束.md §4.2` DDL 模板一致；功能性 v1.1 §3.4 写"is_deleted"是笔误
3. **8 状态投递机**：单一 `status` 字段 + 显示层过滤（候选人侧隐藏 VIEWED_BY_HR）
4. **简历快照**：投递瞬间拷贝 `resume_snapshot_id`，防止候选人后续修改影响历史
5. **ai_score NULL 语义**：表示"待评分"，推断式，不新增 score_status 字段
6. **WITHDRAWN 终态**：仅求职者触发；候选人撤回后自动给 HR 发站内信（→ message 表 sender_role=SYSTEM）
7. **conversation 二元组唯一**：`UNIQUE(hr_user_id, candidate_id, deleted)` 兼容 MySQL 软删
8. **favorite_job 联合唯一**：`UNIQUE(candidate_id, job_id)` 防重复收藏
9. **ACTIVE 简历唯一**：MySQL 不支持函数唯一索引，由 Service 层 INSERT 前校验
10. **avatar 首字符优先级**：`username` > `email 前缀` > `user_id`
11. **展示名优先级**：`resume.basic_name`（投递快照）> `user.username` > `email 前缀`
12. **数据保留期**：ARCHIVED 简历 + 终态投递 ≥ 6 个月；字典软删不级联

### 字符集 / 引擎
- 全部 `utf8mb4` + `utf8mb4_0900_ai_ci` + InnoDB
- 所有业务表加 `deleted TINYINT(1) DEFAULT 0`
- 所有字段写 `COMMENT`
- 索引命名规范：`uk_` / `idx_` / `fk_`
