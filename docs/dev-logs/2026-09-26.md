## 应用三项设计决策（v1.1）

### 文件变动

- docs/需求分析/功能性需求分析.md → 11.2 KB（22 处修改）
- docs/需求分析/非功能性需求分析.md → 2.8 KB（9.4 加一段）
- docs/需求分析/需求分析-修改版.md 与 docs/需求分析/需求分析.md 未改动

### 三项决策的实施

1. **AI 评分触发改为投递瞬间**
   - 4.1.4 投递：新增评分触发 + 候选人不可见
   - 4.2.3 投递管理：HR 浏览不触发 AI，读 ai_score / ai_reason
   - 7.1 AI-2 表格：触发位置 / 预期输出字段更新
   - 7.4 新增条目 10：一次性原则
   - 9.2 AI 降级策略：评分失败 → ai_score = NULL + "待评分"

2. **简历版本：单一 ACTIVE + 历史归档**
   - 4.1.2 简历管理：完整重写用户故事
   - 8.2 resume 表：加 `is_archived` 字段
   - 8.3 实体关系：candidate_profile 1:N resume（仅 1 份 ACTIVE）

3. **撤回投递（WITHDRAWN 终态）**
   - 4.1.4 投递：撤回按钮入口
   - 4.1.5 我的（个人中心）：撤回按钮位置
   - 4.2.3 投递管理：WITHDRAWN 显示规则
   - 5.1 状态枚举：新增 WITHDRAWN 行
   - 5.2 状态流转：新增任意→WITHDRAWN 边；触发规则（仅求职者）
   - 5.3 显示逻辑：候选人 / HR 两侧展示规则 + 全局搜索默认排除
   - 6.2 触发场景：撤回 → 给 HR 发站内信

### 数据生命周期

- 9.4 可维护性：新增数据生命周期管理段
- 软删（is_deleted）+ 列表过滤 + 视图层"显示已结束"开关
- 演示阶段不实做硬删，文档约定保留期 ≥6 个月

### 用户规则记录

- A: WITHDRAWN 触发规则明确写入"仅求职者触发，HR 不可触发"
- B: 撤回 → 自动给 HR 发站内信
- C: 推断式（ai_score NULL 表示待评分），不新增 score_status 字段
- D: is_archived 布尔（与软删风格一致），不用 status 枚举
