## 关键设计要点

### 1. AI-1 Prompt v0.2

```text
严格要求
1. 必须仅返回一个 JSON 对象，不要包含 Markdown 代码块、注释或任何解释文字。
2. 必须包含以下 4 个数组字段，即使原文没有内容也要返回空数组 []，绝对不能省略或返回 null：
   education、work、projects、skills。其中 skills 是字符串数组，其他三个是对象数组。
3. education 数组里的每个对象必须包含 school 字段（学校名）
4. work 数组里的每个对象必须包含 company 字段；项目类似地必须包含 name
5. 日期统一返回字符串 "YYYY-MM" 格式（例如 "2020-08"），无法确定时返回 null
6. 缺失的字段值用 null，不要凭空捏造事实
7. tags / techStack 必须是字符串数组，从原文技术栈行拆出
```

**为什么这样改**：原 prompt 用"必须是数组"表达约束力不足，LLM 会按"原文里有什么就返回什么"理解。改成"必须返回 []"配合 few-shot 后强制力更强。

### 2. LocalDate 反序列化静默丢数组

```java
// 旧代码 — LocalDate 无法解析 "2014-09"
private LocalDate startDate;
```

LLM 实际返回 `"startDate": "2014-09"`（年-月精度），Jackson 用 `ISO_LOCAL_DATE` 解析器要求 `YYYY-MM-DD`。解析失败抛 `JsonProcessingException` → `parseList()` 的 catch 块返回 `List.of()` → 用户看到的"教育经历"是空数组，但数据库里其实存了正确数据。

**修复**：
- DTO 字段改 `String`
- DB 存的就是字符串（JSON 列）
- 反序列化时 Jackson 直接绑字符串，不会失败

### 3. normalize 强校验

```java
public JsonNode normalize(JsonNode raw) {
    // 缺失 education/work/projects → 强制空数组（绝不丢字段）
    // 数组元素缺 school/company/name → putNull 而非丢整条
    // tags/techStack 缺省 → 空数组而非 null
    // skills 非数组 → 按逗号/分号/空白拆
}
```

**为什么这是双保险**：即使 LLM 真的没返回某字段，前端也能拿到结构稳定的 JSON，不会出现 `undefined.xxx` 报错。

### 4. 删除 + 重新上传流程

```text
候选人视图：
  view 模式 ─[重新上传]─► 删除（弹窗确认）─► upload 模式 ─[选文件]─► upload 模式 + AI 解析
  view 模式 ─[删除]─► 删除（弹窗确认）─► upload 模式
  view 模式 ─[编辑]─► edit 模式 ─[保存]─► view 模式
  edit 模式 ─[取消]─► 放弃修改（dirty 提示）─► view 模式
```

后端 `DELETE /api/resumes/{id}`：
1. 校验 ownership（候选人本人）
2. 收集所有 `resume_attachment` 行，逐一 `Files.deleteIfExists(absolutePath)`（失败仅 warn，不抛）
3. 软删所有 attachment 行（`@TableLogic` 自动 `is_deleted=1`）
4. 软删 resume 行（`@TableLogic` 自动 `is_deleted=1`）

**为什么用软删而不是物理删除**：满足设计文档 `功能性需求分析 §9.4`「ARCHIVED 简历保留期 ≥ 6 个月」要求；候选人误删可在 DB 里找回。

### 5. 前端三态切换

```
mount → fetchCurrent
  ↓
  ACTIVE → view 模式（默认）
  空 → upload 模式

view → [编辑] → edit 模式
edit → [保存] → view 模式（refresh store.current）
edit → [取消] → dirty ? 提示确认 : 直接 view
view → [删除/重新上传] → 二次确认 → DELETE API → upload 模式
```

### 本轮修复

**A. 流程重构（按你的要求）**

| 旧流程 | 新流程 |
|---|---|
| upload → AI 解析 → **view** 模式 → 点「编辑」→ edit 模式 → 保存 → view | upload → AI 解析 → **edit** 模式（AI 填好的字段全在表单里）→ 修改 → 保存 → view |
| 删除按钮被「保存-编辑-删除」语义模糊 | 「重新上传」「编辑」「删除」三个按钮颜色不同，data-testid 标识 |

**B. 删除实现改成最保底方式**

```diff
- await ElMessageBox.confirm(...各种复杂 option)  // 可能因 Element Plus 版本兼容问题弹出失败
+ if (!window.confirm('删除当前简历？...')) return  // 浏览器原生对话框，永远可靠

  await store.remove(targetId)
- // 手动同步 store / 切换 mode（容易漏状态）
+ window.location.reload()  // 整页重载，任何状态不一致都被消除
```

**为什么用 `window.confirm` + `window.location.reload()`**：
- `ElMessageBox` 在某些 Element Plus 版本 / Vite HMR 边界下可能因 z-index 或模态层问题导致弹窗失败，用户看不到 confirm
- `window.confirm` 是浏览器原生 API，100% 可靠
- 删除成功后 `location.reload()` 比手动同步 Pinia store 更彻底：避免任何残留的「看起来没删掉」错觉

**C. 保存按钮**

旧逻辑 `:disabled="!dirty && !!store.current"`（无修改就禁用保存）。新逻辑：始终启用——上传后用户即使不改 AI 填的字段也能直接保存确认。

**D. 调试支撑**

- 每个按钮加了 `data-testid` 属性（`btn-reupload` / `btn-edit` / `btn-delete` / `mode-upload` / `mode-view` / `mode-edit`）
- 所有关键函数（`onUploadChange` / `enterEdit` / `save` / `reupload` / `remove` / `onMounted`）都加 `console.log('[ResumeEdit] xxx', ...)`
- 你可以在浏览器 DevTools 的 Console 面板验证按钮是否触发（看到 `[ResumeEdit] delete click, hasActive = true, currentId = 122` 即说明点击成功）

**Bug 1（Vue 编译错）**：模板用 `<el-icon-upload-filled />`，但 `@element-plus/icons-vue` 包导出的组件名是 `UploadFilled`（不是 `el-icon-upload-filled`）。`main.js` 通过 `app.component(key, component)` 通配注册所有图标，但 key 是 `UploadFilled` 而不是 `el-icon-upload-filled`，所以 Vue 在 render 时找不到这个名字，触发 warn + 渲染中断。**这个 warn 不致命，但很可能在 el-icon 内部导致 slot 渲染失败，向上冒泡成 el-card #header 整个 slot 不显示 → 你看到的「按钮不见」。**

1. **修图标**：从 `@element-plus/icons-vue` 显式 import `UploadFilled`：

4. **底部按钮 data-testid 全部就位**：

## 追加 · 移除工作/项目技术栈字段 + 修复技能输入（17:50）

### 用户反馈

> "在编辑'工作经历模块'时，你的代码给每个工作经历的'技术栈'规定了输入的方式（用逗号分割等等），但实际输入有很大问题，任何符号都会触发自动填充大量'/'符的bug"
> "我的建议是去掉每个项目经历小模块中的技术栈这一栏，反正下面有技能模块，项目经历就不需要刻意写技术栈了"
> "简历编辑中的技能模块在添加时不支持英文输入，且经常出现输入+回车后添加失败的情况"

### Bug 根因

**Bug 1（技术栈输入 bug）**：原代码用 `el-input` 的 `:model-value` + `@update:model-value` 双向驱动 `item.tags`，外层 `joinList(item.tags)` 用 `" / "` 分隔显示。split 正则 `[/,，;；\s]+/` 只切 `,，;；\s`，**不切 `/`**。所以用户输入 "Java / Spring" 后被 split 成 `["Java", "/", "Spring"]`，再 joinList 又把 `/` 作为分隔符插入 → 显示成 "Java / / Spring / Spring /"，看起来就是"自动填充大量/符"。

**Bug 2（技能英文/回车失败）**：原代码用 `document.getElementById('skill-input')` 直接操作 DOM（违反 Vue 响应式），且 `input.value = ''` 在 Element Plus 的 el-input + IME 输入法合成下会丢失未提交的字符。英文用户在按回车前如果触发了 IME 组合，`keyup.enter` 监听不到；或者 el-input 内部有自己的值管理，外部 `input.value = ''` 会被覆盖。

### 本轮修改

| 改动 | 解决 |
|---|---|
| 删除 `WorkItem.tags` 的前端编辑（`<el-input>` 整块去掉） | Bug 1：彻底消除技术栈输入交互 |
| 删除 `ProjectItem.techStack` 的前端编辑 | Bug 1：同上 |
| 删除 view 模式工作/项目卡片中的 `tags` / `techStack` 渲染 | Bug 1：视觉上也消失 |
| 删除 `joinList` 函数调用（保留函数定义，已无引用） | 清理 |
| `addSkill` 改用 `newSkill` 响应式 ref + 模板 `v-model="newSkill"` 绑定 | Bug 2：标准 Vue 响应式，不依赖 DOM |
| 模板技能 input：`v-model="newSkill" ref="skillInputRef"` + `@keyup.enter="addSkill"` | Bug 2：IME 安全（v-model 同步输入），回车准确触发 |

**后端 + AI 不变**：
- `WorkItem.tags` / `ProjectItem.techStack` 字段仍在 DTO 里保留，AI 仍解析写入数据库（数据完整性）
- 后端接收 `Update` 请求时这两个字段是可选的，前端不传就传空数组
