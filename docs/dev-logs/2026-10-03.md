## 关键设计要点

### 后端

1. **LlmClient**：OpenAI Chat Completions 协议 + Caffeine 缓存（SHA-256 key）+ ai_call_log 写入。配置缺失时抛 400 / 超时 / 失败抛 500。
2. **MailService**：`app.mail.enabled=true` 走 SMTP，否则 console 输出（演示态）。重构 AuthServiceImpl 复用此服务。
3. **FileStorageService**：`./uploads/{type}/{yyyy-MM}/{uuid}.{ext}`，按 type 白名单。新增 `resolveAbsolute()` 避免业务代码用 `@Value`。
4. **ResumeTextExtractService**：先 Python 子进程（30s 超时），失败回退 PDFBox / POI。
5. **ResumeService**：单一 ACTIVE 校验（已有 ACTIVE 抛 400）+ AI-1 失败降级（空字段 + `aiParsed=false`）+ JSON 字段读写（教育/工作/项目）。
6. **AuditLogService**：`beforeValue` / `afterValue` 是 MySQL JSON 列，写入前 `objectMapper.writeValueAsString()` 序列化为合法 JSON。
7. **CORS**：开发态允许 `http://localhost:5173` 与 `http://127.0.0.1:5173` 双写，覆盖 Vite 两种 host。

### 前端

1. **顶栏**：毛玻璃（backdrop-filter），不显示角色标签；右上角圆头像 + 昵称，点击跳 Profile；登录态变退出按钮
2. **首页**：蓝渐变 hero + 3 列快速入口（按角色动态）+ 3 列数据 + 2 列推荐职位 + 底部 CTA + footer
3. **登录注册**：左蓝渐变 hero + 右白色表单，element-plus label 顶部对齐
4. **Profile**：左 Tab（按角色显示对应选项）+ 右内容卡，干净清爽
5. **axios 拦截器**：自动解 Result 包装；401 清 token 跳登录；错误消息映射为中文（401 请先登录 / 403 无权限访问 / 404 资源不存在 / 5xx 服务器异常 / 网络错误 网络连接失败）
6. **Pinia 持久化**：auth store 用 localStorage，刷新不丢登录态；过期自动清
7. **元素主题色**：蓝白主色 `#1d6fd8` + 辅助 `#06b6d4`，覆盖 Element Plus 默认蓝

### 根因 2（login 500）

`{"code":500,"message":"系统异常，请稍后重试"}` 来自 `GlobalExceptionHandler.handleException`（捕获非 BusinessException）。

可能原因（待确认）：
- DB 连接 / schema 问题
- `hr01@qq.com` 不存在（应返回 401 而非 500，但可能 NPE）
- JWT 签发失败

**改进**：`AuthService.login` 加详细日志（log.info 登录失败原因 / log.error 签发 JWT 异常栈），定位后端根因。

### 文件变动

## 追加 · LLM 返回内容解析容错修复（00:25-00:30）

### 用户反馈

测试 AI 一键润色，弹「内容解析失败」。

### 根因（用户查 ai_call_log 确认）

MiniMax 在生成内容前会先输出 `<think>...</think>` 推理块，然后才是真正的 JSON 响应。原始代码 `objectMapper.readTree(responseText)` 直接解析失败，抛 500。

示例日志（用户提供）：
```
<think>The user wants me to polish a job posting for a Python Backend Engineer position...
I need to:
1. Expand the description to at least 3 items based on the title and industry context
2. Expand requirements to at least 3 items
3. Generate keywords
```
（JSON 在 600 字符预览后被截断）

### 修复方案

`LlmClient` 加 `extractJson(text, functionCode)` 容错抽取器，按顺序尝试：

1. 去 `<think>...</think>` 块（MiniMax 风格）
2. 直接解析
3. 去 markdown code fence（`` ```json ... ``` ``）重试
4. 截取首个 `{...}` 子串重试
5. 截取首个 `[...]` 子串重试
6. 全部失败 → 抛错，errorMessage 含原始响应前 200 字

### 文件变动

- `llm/LlmClient.java`：
  - `callJson()` 用 `extractJson()` 替换原 `objectMapper.readTree()`
  - 新增 `public static extractJson(String text, String functionCode)` 容错抽取器
  - 新增 `tryParse()` 私有辅助方法
  - 新增 `failed()` 抛错并日志原始响应
  - 正则常量：`THINK_BLOCK`（MiniMax 推理块）、`MD_FENCE`（markdown code fence）
- 测试：`LlmClientJsonExtractTest`（新文件，11 个用例覆盖 5 种返回形态 + 边界情况）

### 验证

```
mvn test → Tests run: 49, Failures: 0
  - 原 38 通过
  - 新增 11 个 extractJson 单测（纯 JSON / 思考块 / markdown fence / 前后缀文字 / 数组根 / 空 / null / 仅思考块 / 纯文字 / 错误信息含原文）
npm run build → 通过（前端无改动）
```

### 收益

- AI-3（一键润色）+ AI-1（简历解析）共用 LlmClient.callJson，**两者都受益**
- 不再因为"LLM 偶尔不听话"就报错
- 失败时日志能看到 LLM 真实返回，调试更高效

### 已知遗留
