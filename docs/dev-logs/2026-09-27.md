## 设计要点

### §0 全局约定（master）
- 鉴权：JWT + 注解拦截器风格（`@LoginRequired` / `@RoleCandidate` / `@RoleHR` / `@RoleAdmin`）
- 响应包装：`Result<T>{code, message, data}` + `PageResponse<T>{total, pageNum, pageSize, list}`
- API 前缀：全部 `/api/...`
- 异步：`@Async` + TaskExecutor（核心 4 / 最大 8 / 队列 200）
- AI 调用：RestClient + 30s 超时 + 失败降级
- Pinia：7 个 store 推荐划分（auth / user / resume / job / application / message / aiChat）

### 8 大落实做法（灵活性保障）
1. 阅读说明段写明"API 路径 / DTO 字段 / 注解命名 / 错误码均为示意"
2. 每张时序图下标注"实际实现可选用等价方案"
3. API 接口段落：endpoint 写，字段名+类型示意，不写 JSON 示例
4. 措辞"推荐 / 建议 / 可选用 / 参考做法"，不写"必须 / 强制 / 统一规定"
5. 数据模型小节只列表名 + 关键字段，不写完整 DDL（指向 数据库设计.md）
6. 前端组件小节只描述页面用途 / 关键交互 / 涉及 store，不写组件树
7. 文档中未提及任何具体参考项目或仿照来源
8. 前端页面描述使用通用名词（"列表 / 详情 / 表单 / 抽屉 / 弹窗 / 悬浮卡片"），未引用具体应用名

### 时序图策略
- 时序图覆盖用例"整个流程"（从用户操作 → 前端 → 后端 → 数据库 / 外部服务 → 返回 → UI 更新）
- 不堆砌每个异常分支；异常分支用 note 概括说明
- 同步实线 / 异步虚线 + note 标注
